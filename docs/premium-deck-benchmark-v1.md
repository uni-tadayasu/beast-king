平均対戦長は8.98プレイヤーターン。各プレイヤーの手番を1ターンとして数える。B0512「王冠竜 レガリア」本体を召喚した試合は2,051件、本体が攻撃した試合は1,858件だった。専用合成魔獣による召喚・攻撃は、この本体の集計に含めない。

## 測定方法

- 対戦相手は、スターター・継承・創世・イベントの**現行48構築**。同一構築は重複集計しない。
- 1シード群につき、各対面を16回、同じ組合せで先攻・後攻を入れ替えて実行した。`48 × 16 × 2席 × 2シード群 = 3,072戦`。
- 両席とも本番の `runAutomatedTurn(game, 'hard')` を使用した。勝敗はゲームが返した結果だけを数え、未完了を勝利として扱っていない。
- 通常32枚＋特殊4枚、同名2枚まで、初期HP5000、手札4枚、場4体、最大エーテル10、既存の先後補正を使用した。打ち切り上限は200プレイヤーターン。
- 調整用のシード `0x5c1a4e71` は最終集計に含めない。最終シードを成績に応じて選び直していない。
- 48構築は追加後の公開カタログに基づく。イベントの混成構築の一部も、新しいレガリア専用カードや専用合成魔獣を採用している。対戦相手を旧カードだけに制限していない。

正確な各対戦相手の通常・特殊デッキは、JSONの `opponentsSnapshot` に保存している。イベント構築はカタログから一部のカードを選ぶため、将来のカタログで再生成した構築が今回と同じとは限らない。

再実行には測定時と同じソースを用い、保存済みの対戦相手スナップショットを渡す。

```js
import {readFile} from 'node:fs/promises';
import {compareOperatorDeck} from './scripts/operator-deck-benchmark.mjs';

const report = JSON.parse(await readFile('docs/premium-deck-benchmark-v1.json', 'utf8'));
for (const seedBase of report.methodology.holdoutSeeds) {
  const result = compareOperatorDeck(report.deck, report.opponentsSnapshot, {
    seedBase,
    seedsPerOpponent: 16,
    maxTurns: 200,
  });
  console.log({seedBase, wins: result.wins, losses: result.losses,
    draws: result.draws, unfinished: result.unfinished});
}
```

「神性能」という強化方針でも、勝利は保証しない。今回の96.68%は上記の構築・本番hard CPU・シード・対戦条件で得た実測値であり、任意の対人戦や将来の構築に対する勝率ではない。実際に102敗しており、100戦100勝や自動勝利を実装・保証するものではない。

## 全プレイヤー共通のカードと構築

B0512の強化は公開カード定義そのものに適用した。攻撃力2400、守備力2600、守護・速攻・吸収、召喚時の敵全体1000ダメージと自分HP1500回復は、使用するアカウントにかかわらず同じである。

公開プレミアム構築はB0512を2枚、新しい専用通常カード15種類を各2枚、専用合成魔獣2種類を各2枚で構成する。**構築の18種類すべてGGR**。サーチ、軽減、召喚保護、再展開などの能力と合法性判定にも運営用の裏補正はない。運営向けの完成構築付与は所有カードの付与であり、カード性能の違いではない。一般プレイヤーもカードを入手すれば同じ構築を使用できる。

新17種類は固定シード `0x72656761` のシャッフルで既存4パックへ割り当て、通常排出対象へ追加した。既存カードのパック所属は移動していない。

## 測定時ソースと公開時の包装

JSONの `measuredHashes` は、実際の測定時に読み取ったソースのSHA-256であり、この記録では変更していない。カード定義は `cardSnapshot`、構築は `deck` と `opponentsSnapshot` でも確認できる。

測定後の公開準備でimport URLなどのキャッシュqueryだけを更新した場合、ファイルハッシュは変わるが、カード性能・ルール・CPU・構築が同一であることを差分で確認できれば性能変更とは区別できる。その場合も元の測定時ハッシュを置き換えず、公開時ハッシュや確認内容を別の記録として追記する。カード値・効果処理・CPUの判断・構築内容に変更がある場合は、今回の成績を変更後の実測として扱わない。

旧運営構築などの既存ベンチマーク文書は、当時の条件における履歴として保持している。
