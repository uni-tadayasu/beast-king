# Beast King 新生版 — Phase 3 / Operator entitlement

本ブランチは公開中の main と既存の保存データを変更しない再構築用です。旧アプリの画面やCSSを読み込まず、画面・操作・ローカルプロフィールを新規実装します。第一弾の既存カードデータと個別イラスト、ソロシナリオを継承し、戦闘エンジンと抽選処理は再構築用の独立モジュールに分離しています。

## 起動

リポジトリをこのブランチに切り替え、ルートで `python3 -m http.server 8000` を実行し、`http://localhost:8000/rebuild/` を開いてください。直接ファイルを開くのではなくHTTPサーバーを使用します。

## 実装範囲

- 初回だけの名前・プロフィール設定（独立保存キー）、スターター4種類
- 第一弾・第二弾合計2,304枚の図鑑・検索・カード詳細、6段階のレアリティ演出
- 32＋4のデッキ編集、所持枚数と同名2枚上限、4スターター選択
- 各1,152枚の第一弾・第二弾パック、12枚入り、秘宝、重複変換
- 全20戦のソロと3段階の練習戦、既存ルールでのCPU戦、合成素材選択、戦績と報酬
- 新デザインの固定画面レイアウト。端末サイズによるページ分割

### 運営専用レガリア
通常版 B1024 は第二弾パックに含まれます。別イラスト版 OP-B1024 は同名・同性能で、一般収録2,304枚とは別の限定印刷です。両パック抽選、通常所持カードの付与、公開図鑑、一般ローカル保存から除外しています。同名2枚制限は通常版と限定版を合算します。専用イラストは `assets/rebuild/operator-regalia.webp` を表示します。素材を登録していない場合は「専用イラスト未登録」と表示します。
`operator-deck.js` は第一弾20枚＋第二弾16枚（限定レガリア2枚を含む）からなる𠮷良原デッキのサーバー統合用構成です。サーバーの `/api/rebuild/operator-deck` に GET（利用権復元）と POST（初回専用コード照合）を実装しました。既存の運営アカウント認証を必須とし、環境変数 `BK_OPERATOR_REGALIA_CODE` のみで照合します。D1 の監査テーブルに利用権を一回だけ記録し、端末連携後も同じアカウントで復元します。公開クライアントに秘密のコードや権限フラグを保存しません。運営アカウントの既存セッションが必要です。API配備後はロゴを7回押し、初回だけ専用コードを入力し、𠮷良原デッキを選択できます。ソロ開始ごとにサーバー照合します。ソロ戦闘自体はクライアント実行であり改変耐性はありません。マルチ・ランクは新カタログ対応のサーバー戦闘と権限検証の接続が必要です。
