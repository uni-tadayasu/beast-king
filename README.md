# ビーストキング｜BEAST KING

全1,152枚のカードからメインデッキ32枚と特殊デッキ4枚を組み、CPUと戦うオリジナルブラウザカードゲームです。PC・スマートフォン・タブレットの画面幅に対応しています。

**公開先:** https://www.beast-king.com/

## 収録内容

| 種類 | 枚数 | 使用するデッキ |
| --- | ---: | --- |
| 魔獣 | 640（通常512・合成128） | 通常はメイン、合成魔獣は特殊デッキ |
| ミラクル | 256 | メインデッキ |
| ギミック | 256 | メインデッキ |
| 合計 | 1,152 | メイン32枚＋特殊4枚 |

通常魔獣512枚の内訳は、アタック型256枚・ディフェンス型256枚です。合成魔獣128枚は別枠で、各カードにモデルを持ちます。

| カード分類 | 内訳 |
| --- | --- |
| ミラクル256枚 | 威力カード128枚・再生カード128枚 |
| ギミック256枚 | 反射カード128枚・魔獣サポートカード128枚 |

威力カードはダメージ・魔獣強化・手札補給を行います。再生カードはハートポイントや魔獣の守備力を回復し、「合成」も再生カードに含まれます。「合成」の効果は合成召喚です。反射カードは攻撃に反応して攻撃元へダメージを返し、魔獣サポートカードは次の自分のターンに味方全体を強化したり、守備力を回復したりします。

オリジンは **山 → 川 → 種 → 草 → 花 → 木** の6種類で、この順に表示します。全カードを最初から使用できます。カード一覧、検索・絞り込み、メインと特殊のデッキ編集、8種類のスターターデッキ、3段階のCPU対戦に対応しています。

全スターターは、魔獣16枚・ミラクル8枚・ギミック8枚のメイン32枚と、各スターターのオリジンに対応した合成魔獣4枚の合計36枚です。ミラクル8枚には「合成」を2枚含みます。

イラストは、魔獣16種類・ミラクル4種類・ギミック4種類・合成魔獣16種類の計40種類の基本モチーフを、カードのシリーズ別に共用しています。

レアリティは、**ノーマル → レア → キラレア → キラキラレア → ギラレア → ギラギラレア** の6段階です。ギラギラレアが最高位です。

## 基本ルール

- メインデッキは32枚ちょうど、特殊デッキは4枚ちょうど。合計36枚で対戦します。同じカードは各デッキに3枚までです。
- メインデッキには通常の魔獣・ミラクル・ギミックを入れます。特殊デッキには合成魔獣だけを入れ、特殊ゾーンに置きます。
- お互いのハートポイントは5,000から開始。攻撃などで0になると敗北し、相手のハートポイントを0にすると勝利します。回復の上限も5,000です。
- 魔獣の攻撃力・守備力、戦闘ダメージ・回復・結界は100単位で表示します。カードの枚数やエーテルのコストは別の単位です。
- 自分のターン開始時に最大エーテルが1ずつ増え、最大値まで回復します。上限は10です。
- 出場ゾーンは通常の魔獣と合成魔獣を合わせて4体まで。ギミックは2枚まで場に出せます。
- 初期手札は4枚。手札の上限も4枚で、自分のターン開始時に4枚になるまで補充します。カード効果によるドローも4枚で止まり、上限により引けないカードは山札に残ります。
- 通常の魔獣と合成魔獣は、召喚した次の自分のターンから1ターンに1回攻撃できます。「速攻」は召喚したターンから攻撃可能です。
- 「守護」を持つ敵がいる場合、攻撃では守護を先に狙います。
- 魔獣への攻撃は下記のモデル比較で判定し、通常の戦闘では反撃しません。「吸収」は戦闘で相手のハートポイントを実際に減らした分、自分のハートポイントを回復します。
- ミラクルは即時発動。ギミックは設置後、条件を満たすと自動発動します。反射カードは攻撃元へダメージを返し、魔獣サポートカードは次の自分のターンに味方全体の攻撃力・守備力を強化したり、守備力を回復したりします。
- 山札が空の状態でドローすると、回数に応じて増える疲労ダメージを受けます。

## モデルと配置

各魔獣カードには「アタック型」「ディフェンス型」のモデルがあります。すべてまっすぐ縦向きに置きます。前は相手へ向かう方向、後ろは自分側です。

| 魔獣の種類・モデル | 出場ゾーンでの配置 |
| --- | --- |
| 通常魔獣・アタック型 | 枠より少し前（相手側） |
| 通常魔獣・ディフェンス型 | 枠より少し後ろ（自分側） |
| 合成魔獣 | モデルにかかわらず、枠の中央にぴったり合わせる |

アタック型の魔獣が攻撃を受けると、守備力にかかわらず必ず消滅し、お墓ゾーンへ移動します。持ち主は、攻撃した魔獣の攻撃力全額をハートポイントへのダメージとして受けます。

ディフェンス型は現在の守備力と相手の攻撃力を比較します。守備力が相手の攻撃力以上なら、魔獣は生存し、守備力も持ち主のハートポイントも減りません。同値も生存・ダメージ0です。相手の攻撃力が守備力を上回る場合は消滅し、持ち主は超過分だけハートポイントが減ります。

| 攻撃を受けるモデル | 相手の攻撃力 | 自分の守備力 | 結果 |
| --- | ---: | ---: | --- |
| アタック型 | 800 | 1,000 | 消滅・持ち主に800ダメージ |
| ディフェンス型 | 800 | 1,000 | 生存・ダメージ0・守備力は1,000のまま |
| ディフェンス型 | 800 | 800 | 生存・ダメージ0・守備力は800のまま |
| ディフェンス型 | 1,000 | 800 | 消滅・持ち主に200ダメージ |

どちらのモデルも通常の戦闘では反撃しません。魔獣への攻撃で持ち主が受けるダメージは、結界を消費せず、そのままハートポイントから差し引きます。ハートポイントへの通常の直接攻撃には結界が適用されます。

合成魔獣も同じモデルの戦闘ルールに従います。ミラクルや反射などのカード効果は守備力を減らすことがあり、守備力が0になると消滅します。再生カードや魔獣サポートカードで回復する場合は、最大守備力を超えません。

## 合成召喚

1. 再生カードに属するミラクル「合成」（M0256、コスト3）を使い、特殊ゾーンの特殊デッキから召喚したい合成魔獣を1体選びます。
2. 自分の手持ち（手札）・出場ゾーン・お墓ゾーンの魔獣カードを、1枚以上選びます。手持ちのみ・出場ゾーンのみ・お墓ゾーンのみでも合成でき、複数のゾーンを混ぜてもかまいません。通常の魔獣も合成魔獣も素材に使えます。素材の指定枚数に上限はなく、オリジンやレシピの条件もありません。
3. 選んだ素材をすべて異世界ゾーンへ送り、合成魔獣を出場ゾーンに召喚します。異世界ゾーンへ送った素材はその対戦中に再利用できません。「合成」のカード自体はお墓ゾーンへ送ります。
4. 素材2枚目以降は、1枚につき合成魔獣の攻撃力・守備力をそれぞれ+100します。消費するエーテルは「合成」の3だけです。

| 素材の枚数 | 攻撃力・守備力への加算 |
| --- | --- |
| 1枚 | 基礎値のまま |
| 2枚 | それぞれ+100 |
| 5枚 | それぞれ+400 |

素材にできるのは自分の通常の魔獣と合成魔獣です。異世界ゾーンへ送ったカードは再利用できません。出場ゾーンが4体で埋まっている場合でも、出場中の魔獣を素材にして召喚する場所を空けられます。召喚前の選択画面でキャンセルした場合は、カードやエーテルを消費しません。

ゲーム紹介と詳細ルールは `about.html` にも掲載しています。

## 保存と対戦

メインデッキ・特殊デッキ・設定は、現在使用している端末・ブラウザ・サイトのローカルストレージに保存されます。ブラウザのサイトデータを消去すると保存内容も削除されます。別の端末・ブラウザ・公開URLへの自動同期はありません。

現在の対戦はCPUとの1人用です。オンライン対人戦は未実装です。

## ローカルで動かす

外部JavaScriptライブラリやビルド処理は不要です。Python 3が利用できる環境では、リポジトリのルートで次を実行します。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開いてください。ES Modulesを利用しているため、HTMLファイルの直接ダブルクリックではなくHTTPサーバー経由で実行します。

## 検証

Node.js 24を使用します。依存パッケージのインストールは不要です。

```sh
npm test
```

カード枚数・ID・名前・効果の整合性、両デッキの制約、戦闘処理、合成素材の選択と異世界ゾーンへの移動、カードの移動、CPU対戦の進行を検証します。

## GitHub Pagesへの自動公開

このリポジトリは、GitHub Pagesの既存設定 **main /（root）** で公開します。`main` に更新を反映すると、GitHub Pagesの標準ビルド・公開処理が自動で実行されます。ゲームのHTML・JavaScript・画像はリポジトリのルートに配置しています。独自ドメイン `www.beast-king.com` を指定する `CNAME` を保持してください。

`.github/workflows/check.yml` は `main` へのpushとプルリクエストで、カードデータ・対戦処理のテストと `app.js` の構文チェックを行います。公開処理はGitHub Pagesの標準機能が担当します。

公開先を変更する場合は、次のコマンドで新しいURLを指定してください。

```sh
node scripts/configure-seo.mjs https://www.beast-king.com/
```

このスクリプトは `index.html` と `about.html` のcanonical・OGP・Twitter Card・構造化データのURLを更新し、`sitemap.xml` と `robots.txt` を生成します。リポジトリ名を含むサブパスと独自ドメインのどちらにも対応しています。SNS共有画像は `assets/social-ogp.jpg`（1,200 × 630）です。
